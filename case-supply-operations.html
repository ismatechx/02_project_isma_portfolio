Case Study · 01

Supply Operations
at scale.

A 16-KPI Tableau dashboard for Zuci Systems' end-to-end supply operation — cut report turnaround by 25% and lifted operational efficiency by 15%.

Role
Senior BI Analyst
Client
Zuci Systems · Supply Ops
Period
2021 – 2025
Team
Solo + cross-functional

The problem

Supply, Finance, and HPMT teams were running on spreadsheet exports and ad-hoc queries. Decisions waited on reports; reports waited on people.

Each weekly review cycle involved pulling data from disparate sources (procurement systems, finance ledgers, supplier portals), reconciling them by hand, and authoring slide-by-slide commentary. The same KPIs were re-built each cycle, often with subtle inconsistencies.

Stakeholders needed a single source of truth that covered Strategic Sourcing, Procurement, IT Spend, and end-to-end Supply Ops — and that they could trust without re-validating it themselves.

Constraint The output had to be presentable to senior leadership, drillable for analysts, and robust under daily refresh — without adding a maintenance person.

Approach

One dashboard, four lenses, sixteen KPIs — built to scale without becoming someone's full-time job.

01

Map the questions before the data

Workshopped with Supply, Finance, and HPMT to extract the actual decisions each team makes weekly. Translated those into 16 KPIs — not the other way around.

02

Consolidate sources via SQL + Tableau Prep

Built reusable data flows that joined procurement, finance, and supplier data on a stable key, with validation steps to catch reconciliation drift before it reached the dashboard.

03

Design the dashboard as a decision tool

One executive overview (16 KPIs at a glance), drill-down views per pillar, supplier KPI matrix, Actual vs Forecast, and OTIF delivery monitoring. No vanity charts.

04

Make refresh cheap

Set up automated refresh on Tableau Server with validation alerts. Failures surfaced before stakeholders saw stale data — and the dashboard ran itself for years.

What I'd do differently today

If I rebuilt this in 2026, the BI piece stays — but the validation layer changes. I'd put a small LLM-based reconciliation agent on top: have it explain in plain English why two numbers disagree across systems, instead of leaving an analyst to dig.

That's the bridge between this case study and where I'm heading — same problem (decision speed), new tooling (Claude API + RAG over source-of-truth docs).
